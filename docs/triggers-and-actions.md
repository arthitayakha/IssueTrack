# Triggers & Actions — แนวคิดและการใช้กับระบบ

> เอกสารนี้เป็นผลจากการศึกษา/หาข้อมูล ยังไม่ใช่งานที่ต้องทำในโค้ด
> อัปเดตล่าสุด: 2026-10-21

---

## 1. Trigger & Action คืออะไร

**Trigger** = เหตุการณ์ที่เกิดขึ้นในระบบ ("เมื่อ...")
**Action** = สิ่งที่ระบบทำอัตโนมัติตามมา ("แล้ว...")
**Rule** = Trigger + Action

```
เมื่อ [Trigger]  →  แล้ว [Action]
```

เปรียบเทียบเหมือนระบบรักษาความปลอดภัยตึก:
- 🔔 กริ่งประตูดัง (Trigger) → 🚪 ประตูเปิดอัตโนมัติ (Action)

| Action | ผลลัพธ์ |
|--------|---------|
| บันทึก activity log | เขียนลงตาราง `activity_logs` |

## 3. กรณีที่ต้องล็อก (Block) — 2 ระบบแยกกัน

### ระบบ 1: Column Lock (ล็อกคอลัมน์)
- **ล็อกระดับ:** คอลัมน์/สถานะ
- **พฤติกรรม:** การ์ด **เข้าได้ ห้ามออก** (ตามที่ตกลง)
- **ใครล็อก:** admin (toggle ในหน้าสถานะเท่านั้น)
- **ใครปลด:** admin
- **สร้างกฎเองได้:** ไม่ได้ (เป็น toggle ในหน้าเท่านั้น)

### ระบบ 2: Card Lock Rule (ล็อกการ์ดผ่านกฎ)
- **ล็อกระดับ:** รายการ์ด
- **พฤติกรรม:** การ์ดถูกล็อก → ลากย้ายไม่ได้เลย
- **ใครล็อก:** ระบบอัตโนมัติตามกฎ (เช่น ลากไป Done → ล็อก)
- **ใครปลด:** admin + programmer (เลือกได้)
- **สร้างกฎเองได้:** ได้ (เลือก trigger + action เอง)

### ตารางเปรียบเทียบ
| | Column Lock | Card Lock Rule |
|---|---|---|
| ล็อกที่ | คอลัมน์ | การ์ด |
| พฤติกรรม | เข้าได้ ห้ามออก | ลากไม่ได้เลย |
| ใครล็อก | admin | ระบบ (ตามกฎ) |
| ใครปลด | admin | admin + programmer |
| กฎเอง | ไม่ได้ | ได้ |

## 4. เคสต่าง ๆ ที่ต้องพิจารณา

### เคส Trigger
| เคส | ตัวอย่าง |
|-----|----------|
| สร้าง issue | ลูกค้าแจ้งปัญหาใหม่ |
| แก้ไข issue | แก้ title, description, priority |
| ลากการ์ด | Backlog → Doing, Doing → Done |
| มอบหมายงาน | มอบหมาย programmer |
| ลบงาน | ลบ issue |
| กู้คืนงาน | กู้คืนจาก cancelled |
| คอมเมนต์ | มีคอมเมนต์ใหม่ |
| เปลี่ยนสถานะ | เปลี่ยน issue status |
| แนบไฟล์ | อัปโหลด attachment |
| ถึง deadline | วันครบกำหนดใกล้ถึง/ผ่านมา |
| ไม่มี activity นาน | issue ค้างอยู่ X วัน |
| เปลี่ยน priority | priority สูงขึ้น/ต่ำลง |
| ลากกลับ | ลากกลับไปสถานะเดิม (resume) |
| ลากออกจาก Done | ลากออกจากสถานะสุดท้าย |

### เคส Action
| เคส | ตัวอย่าง |
|-----|----------|
| จับเวลา | เริ่ม/หยุด timer |
| บันทึก activity | เขียน activity log |
| แจ้งเตือน | ส่ง notification |
| บล็อกการกระทำ | ห้ามลาก, ห้ามแก้ |
| เปลี่ยนค่า | อัปเดต field อัตโนมัติ |
| มอบหมาย | assign ให้คนอื่น |
| ส่งอีเมล | แจ้งเตือนทางอีเมล |
| สร้าง issue อัตโนมัติ | clone issue จาก template |
| เปลี่ยนสถานะอัตโนมัติ | ย้ายไปสถานะถัดไป |
| คำนวณค่า | คำนวณ SLA, เวลาเฉลี่ย |
| บล็อก + แจ้งเตือน | ห้ามทำ + บอกเหตุผล |

### เคสพิเศษที่ต้องจัดการ
| เคส | ปัญหา |
|-----|-------|
| กฎซ้ำกัน | 2 กฎ trigger เดียวกัน → ทำอันไหนก่อน? |
| กฎขัดแย้ง | กฎ A บอกให้ทำ X, กฎ B บอกห้ามทำ X |
| ห้ามเคลื่อนย้าย | บล็อกแล้วผู้ใช้ควรเห็นอะไร? (toast error?) |
| issue ใหม่ไม่ fix Backlog | ลูกค้าเลือกสถานะเอง → validate ยังไง? |
| trigger ไม่มีกฎ | ไม่มีอะไรเกิดขึ้น → ทำเหมือนเดิม |
| กฎถูกปิด/ลบ | ปิดกฎชั่วคราว แล้วเปิดใหม่ได้ |
| Chain (กฎซ้อน) | กฎ A trigger → action เป็น trigger ของกฎ B ได้ไหม? |

## 5. แนวทางแก้ปัญหา

### ปัญหา 1: กฎซ้ำกัน / ขัดแย้ง
- ให้กฎมี **priority** (int) → ตัวเลขสูงกว่าทำก่อน
- priority เท่ากัน → เรียงตาม `created_at`
- กฎ **block** มี priority สูงสุดเสมอ (เช็คก่อน execute อื่น)

### ปัญหา 2: กฎ "ห้ามเคลื่อนย้าย"
- กฎ block มี `block_reason` (ข้อความบอกเหตุผล)
- ตอนลากการ์ด → API return 403 + message
- ฝั่ง frontend → toast error: "ไม่สามารถย้ายได้: [เหตุผล]"
- เก็บใน activity log ว่ามีคนพยายามทำแต่ถูกบล็อก

### ปัญหา 3: issue ใหม่ไม่ fix Backlog
- เพิ่ม field `initial_status_id` ในตาราง `issues` (nullable)
- ตอนสร้าง issue → รับ `status_id` จาก frontend
- validate: status_id ต้องเป็นคอลัมน์ที่มีอยู่จริงในบอร์ด
- ถ้าไม่ส่งมา → default เป็น Backlog (เหมือนเดิม)

### ปัญหา 4: กฎซ้อนกัน (Chain)
- **ไม่ให้ซ้อน** (ง่ายกว่า, หลีกเลี่ยง infinite loop)
- หรือให้ซ้อนได้แต่มี **max depth = 3** ป้องกัน loop

### ปัญหา 5: Performance
- แมป trigger → rules ใน memory (Map)
- ตอนมี trigger เกิดขึ้น → ดึงกฎที่เกี่ยวข้องมา execute
- cache rules ใน memory + refresh เมื่อมีการแก้ไข

## 6. โครงสร้างข้อมูล (เบื้องต้น)

```sql
-- board_columns
ALTER TABLE board_columns ADD COLUMN is_locked BOOLEAN DEFAULT FALSE;

-- issues
ALTER TABLE issues ADD COLUMN is_locked BOOLEAN DEFAULT FALSE;
ALTER TABLE issues ADD COLUMN locked_at TIMESTAMPTZ;
ALTER TABLE issues ADD COLUMN locked_by INTEGER REFERENCES users(id);

-- rules
CREATE TABLE rules (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255),
  trigger VARCHAR(100),       -- 'card.moved', 'card.created', ...
  action VARCHAR(100),        -- 'lock_card', 'unlock_card', 'notify', ...
  priority INT DEFAULT 0,
  is_blocking BOOLEAN DEFAULT FALSE,
  block_reason VARCHAR(255),
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE rule_conditions (
  id SERIAL PRIMARY KEY,
  rule_id INT REFERENCES rules(id),
  field VARCHAR(100),         -- 'status', 'priority', ...
  operator VARCHAR(20),       -- '=', '!=', 'in', ...
  value VARCHAR(255)
);
```

## 8. สถานะการทำ

- **ตอนนี้:** เป็นการศึกษา/หาข้อมูลเฉย ๆ ไม่ต้องทำอะไรในโค้ด
- **ความตั้งใจ:** ยังไม่ได้สั่งทำ รอให้พี่ตัดสินใจว่าจะทำหรือไม่
- **หมายเหตุ:** โครงสร้าง/UI ข้างบนเป็นแนวทางเบื้องต้น ยังไม่ใช่ข้อตกลงขั้นสุดท้าย
