### 0.2 กติกาสำคัญ (อ่านก่อนทุกครั้ง)

1. **ก่อนเริ่มแต่ละ EV: pause กฎอื่นทั้งหมด** ใน `/automation` — เหลือไว้เฉพาะกฎของ EV นั้น ไม่งั้นผลทดสอบปนกัน
2. **กฎ "บังคับลากการ์ดทีละคอลัมน์" (`issue.move_step_only`) ถูก seed มาเปิดอยู่แล้ว** — EV ที่ต้องลากอิสระวให้ pause ก่อน แล้ว **resume คืนหลังจบเสมอ** (ยกเว้น EV ที่กำลังเทส action นี้เอง)
3. **skip reason เห็นแค่ใน log เซิร์ฟเวอร์ (ฝั่ง API)** — UI ไม่แสดง เช่น `timer already running` / `not in trash`
4. ทำ **ทีละ action**: เลือก action ในแท็บ → บันทึก → จุดชนวน → ตรวจผล → กลับไปแก้กฎเปลี่ยน action ถัดไป (หรือลบแล้วสร้างใหม่) → **pause กฎก่อนเปลี่ยนแถว**

### 0.5 ข้อเท็จจริงของเอนจินที่ต้องรู้ (ก่อนอ่านคอลัมน์ "ผลที่คาดหวัง")

1. **action 3 ตัวนี้ engine คืน `skipped` เสมอ** — เพราะเป็น "นโยบาย" ไม่ใช่ event: `issue.move_step_only` (`checked before the move, not on it` — ผลมาจาก guard ตอนลากจริง), `issue.notify_stale` (`checked by the daily sweep`), `issue.hide_from_board` (`checked at query time`)
2. **skip reasons ที่เป็นไปได้** (ดูใน log): `timer already running` · `no running timer` · `no user to own the timer (assign the card first)` · `label already present` · `label not present` · `already deleted` · `not in trash` · `no priority/category/position/label configured` · `no active user holds position` · `no message configured` · `status lock is enforced at read time, not per card`
3. **action ที่เขียนข้อมูลตรง → ไม่มี notification และไม่มี activity log** (set_priority, set_category, lock, unlock, labels, open_analysis, open_resolution, delete, restore, allow_time_entry, start/stop/reset timer) — **ยกเว้น 3 ตัวนี้:** `issue.move_status` แจ้งเปลี่ยนสถานะ (เมื่อสถานะเปลี่ยนจริง), `issue.assign`/`issue.unassign` แจ้งมอบหมาย, `issue.comment` สร้าง activity `comment.created` (automated) — **แต่ comment ของกฎไม่ส่ง notification**
4. **action ไม่ trigger rule ตัวอื่นต่อ** (เอนจินกัน re-entry เอง) — กฎ A ย้ายการ์ด ไม่ทำให้กฎ "การ์ดถูกลาก" ตัวอื่นยิงตาม
5. **`issue.lock` มี 2 ทาง:** ถ้ากฎมีเงื่อนไข `to_status` (เฉพาะ EV01) = **status lock** — คำนวณตอนอ่าน ล็อกทุกใบในสถานะ pause ปลดทันที, ไม่มี flag ค้าง; ถ้าไม่มี = เขียน **flag รายใบ** `is_locked` — **ค้างแม้ pause กฎ** ต้องปลดด้วยปุ่มปลดล็อก/`PUT /issues/:id/unlock`
6. **`work_session.start` หาเจ้าของ timer 3 ขั้น:** ผู้รับการ์ด → ผู้กระทำ → ผู้สร้างกฎ (ไม่เจอ = skip)
7. **ผลของ `issue.set_time` = ไม่มีใน Step ② เลย** (`status: unsupported` ถูกซ่อนทุกที่) — จึงไม่อยู่ในขอบเขตเอกสารนี้

## EV17 — การ์ดในสถานะ {status} ที่ค้างอยู่เกิน {days} วัน · `board.policy` + template `stale_in_status` (2 การกระทำ)
